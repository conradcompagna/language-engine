# Dictionary SQLite Port Function Audit

Date: 2026-03-27

## Method

I reread every function in `static/dictionary_engine.js` and `static/dictionary_client.js`, then compared each one against the active SQLite stack in `static/dictionary_postprocessor.js`, `sqlite_segmenter.py`, `dict_lookup_sqlite.py`, `router.py`, and `convert_tsv_to_sqlite.py`. This audit uses the current old baseline files in the repo, not older backups.

Legend:

- `A redundant`: architecture-specific to the old browser-TSV system, already inert in the legacy baseline, or reduced to a compatibility shim.
- `B fully ported`: the behavior still exists in the active SQLite stack, even if the owner changed files or moved server-side.
- `C some stuff left behind`: non-redundant behavior is only partially present in the current SQLite system.

Totals: `A=99` `B=221` `C=21` across `341` legacy functions.

Confirmed high-confidence `C` themes before the per-function list:

- Korean `eumhun` secondary-form indexing was not reproduced in the SQLite form index, so some old Korean form lookups are no longer reachable.
- Korean synthetic `-?` stem indexing for verbs/adjectives was not recreated in the SQLite form index, so some stem lookups now miss.
- The debug scoring payload dropped `lemma_hints`, `surface_exact_events`, and `lemma_exact_events`, even though `debug_panel.py` still expects them.
- Legacy normalized-match decoration metadata is not recreated end to end in the current lookup payloads.
